# A/B/C/D/F 多策略中美股模拟交易系统设计

日期：2026-07-27
状态：已批准

## 1. 目标

构建一套只交易 A 股和美股的多策略模拟交易系统，以相同研究宇宙、数据时间点、资金、成交规则和公共风控，并行比较五套独立策略：

- A：基于 `daily_stock_analysis` 的市场状态路由与技术/事件策略
- B：基于 `ai-hedge-fund` 的多因子、多投资流派、组合经理策略
- C：基于 `TradingAgents` 的分析师、多空辩论、交易员和风险团队策略
- D：基于 `ai-berkshire` 的商业质量、价值、安全边际和管理层策略
- F：抽取四个项目最擅长的能力，组成串行融合策略

系统同时支持：

1. 十年确定性历史回测
2. 代表性历史截面的完整 Agent 重放
3. 从当前日期开始的五套前向模拟盘
4. 买入、加仓、减仓、卖出、现金管理
5. 可审计的决策、订单、成交、持仓、净值和模型调用记录

本系统只用于模拟交易，不接入真实券商下单。

## 2. 上游项目基线

设计调研基于以下仓库在 2026-07-27 拉取到的版本：

| 项目 | 调研提交 | 在本系统中的角色 |

| ZhuLinsen/daily_stock_analysis | `905c339` | A 策略；F 的初筛阶段 |
| virattt/ai-hedge-fund | `9557e64` | B 策略；F 的组合与风险阶段 |
| TauricResearch/TradingAgents | `a33fd4c` | C 策略；F 的多 Agent 研究阶段 |

原则：不直接把四个仓库粗暴合并，也不让其各自的数据抓取、账本和成交实现并存。它们提供策略思想与可适配模块；本项目维护唯一的数据契约、历史时钟、模拟券商和绩效口径。

## 3. 实验边界

### 3.1 市场和交易权限

- 仅支持 A 股和美股
- 纯多头
- 无杠杆
- 不做空
- 不交易期权、期货、融资融券
- 不做盘前盘后交易
- 看空信号转换为不买、减仓或清仓

### 3.2 账户

每个策略拥有完全隔离的账户：

- A 股子账户：初始资金人民币 1,000,000 元
- 美股子账户：初始资金美元 100,000 元
- 五套策略共十个市场子账户
- 策略之间不得共享现金、持仓或调拨资金
- 美股绩效可按每日汇率折算成人民币做总览，但原币账本不可丢失

### 3.3 持仓周期

- 主要持仓周期：20–120 个交易日
- 单笔最长观察期：一年
- 允许策略在逻辑证伪、风险触发或目标实现后提前退出
- 最长期限不是强制盈利退出；到期必须重新评估并形成新的可审计决策

## 4. 研究宇宙

### 4.1 前向模拟股票池

- A 股 100 只
- 美股 100 只
- 启动时确定，原则上固定一年
- 年内只因退市、合并、长期停牌或数据持续不可用等客观原因替换

### 4.2 入池约束

共同要求：

- 上市至少三年
- 具备足够日均成交额和历史数据覆盖
- 行业、风格和市值层级分散
- 同时包含成长、价值、周期、高股息和高波动样本
- 不根据未来收益选股

A 股额外排除：

- ST/*ST
- 长期停牌
- 北交所
- 财务数据严重残缺

美股额外排除：

- OTC
- 仙股
- 极低流动性证券
- 无稳定财务与公司行动数据的证券

### 4.3 历史回测股票池

禁止使用当前仍存续的 200 只股票直接回测十年。历史回测按年度、仅使用当时已知信息重建股票池，并保留后来退市、被并购或陷入困境的股票，以降低幸存者偏差。

## 5. 历史数据和时间语义

### 5.1 数据期限

- 推荐拉取最近十年
- 前一年可作为技术指标预热期
- 上市不足十年的股票从可获得的稳定数据期开始

### 5.2 Point-in-time 约束

每条可影响交易的记录至少包含：

- `period_end`：数据所属期间
- `published_at`：来源公开发布时间
- `available_at`：系统允许策略使用的时间
- `ingested_at`：本系统抓取时间
- `source`：数据来源
- `source_record_id` 或内容哈希

历史时钟位于时间 T 时，只允许读取 `available_at <= T` 的数据。财报所属季度不是财报可用时间。

### 5.3 数据类别

1. 行情：原始与复权 OHLCV、成交额、换手率、停牌、涨跌停
2. 公司行动：分红、拆股、送转、合并、退市、代码变化
3. 财务：三大报表、关键指标、股本和实际公告日期
4. 估值：PE、PB、PS、股息率及可复算字段
5. 市场：基准指数、行业指数、中美交易日历、USD/CNY、无风险利率
6. 事件：财报、回购、增发、高管变更、处罚、诉讼和重大交易
7. 新闻：标题、摘要、来源、发布时间、抓取时间

历史新闻缺失时必须明确标记，不允许用当前新闻回填过去。

## 6. 系统架构

主链路：

`数据采集 → 原始数据层 → 规范化/PIT数据层 → 历史时钟或实时快照 → 策略适配器 → 公共风控 → 订单 → 模拟券商 → 账本 → 绩效与审计`

核心组件：

### 6.1 Data Ingestion

负责从可替换数据提供商拉取行情、财务、公司行动、交易日历和汇率。数据源失败不能静默返回空值；失败必须进入数据质量状态。

### 6.2 Point-in-Time Store

统一存储规范化历史数据，并按 `available_at` 提供快照查询。策略不得直接绕过该层调用外部实时 API。

### 6.3 Universe Builder

- 构建年度历史股票池
- 构建前向模拟固定股票池
- 记录每只股票入池/出池原因
- 对每次股票池生成保存完整输入和版本

### 6.4 Strategy Adapter

五套策略遵循统一接口：

输入：

- `as_of`
- `market`
- `universe_snapshot`
- `market_snapshot`
- `portfolio_snapshot`
- `strategy_config_version`

输出：

- 标的
- `BUY/HOLD/REDUCE/SELL`
- 目标仓位
- 置信度
- 核心论点
- 证伪条件
- 数据引用
- 模型与提示词版本

策略只提出目标仓位，不直接修改账户。

### 6.5 Risk Engine

公共风控只提供不可绕过的灾难性约束：

- 单股硬上限 15%
- 单一行业硬上限 30%
- 每个市场最多同时持有 10 只
- 单日新建仓不超过可用资金 30%
- 允许 100% 持有现金
- 从历史最高净值回撤 15% 时暂停新开仓
- 回撤 20% 时将风险敞口减半并进入审查状态

策略自身的止损、估值退出和论点证伪不由公共层统一替代。

### 6.6 Execution Simulator

- T 日收盘后形成信号
- T+1 下一可交易日开盘尝试成交
- 按开盘价加方向性滑点
- 费用规则配置化，并按成交日版本保存
- A 股执行 100 股整数手、T+1、涨跌停和停牌规则
- 美股执行交易日历、公司行动和可交易状态规则
- 不允许当日收盘数据产生信号后按同一收盘价成交

### 6.7 Ledger

使用双分录式不可变事件账本记录：

- 现金变化
- 订单和成交
- 持仓批次和成本
- 已实现/未实现盈亏
- 股息、税费和公司行动
- 每日 NAV

纠错通过冲销事件完成，不直接改写历史成交。

### 6.8 Evaluation

统一计算：

- 累计和年化收益
- 波动率
- 最大回撤
- Sharpe、Sortino、Calmar
- 胜率、盈亏比、换手率
- 相对指数和等权股票池的超额收益
- 选股、买入择时、卖出、仓位管理和风控贡献
- Agent 调用量、token 成本和单位超额收益成本

## 7. 策略定义

### 7.1 A：daily_stock_analysis

运行频率：每日。

保留多策略路由：根据市场状态，从趋势、均线、量价、事件、热点、成长和预期等策略中选择适配策略，而不是全部平权投票。

买入条件：

- 策略与市场状态匹配
- 综合评分达到阈值
- 趋势、成交和风险检查通过
- 候选排名进入可建仓区间

卖出条件：

- 路由策略明确转空
- 趋势结构破坏
- 策略止损/止盈触发
- 催化事件证伪
- 持仓超过最长观察期且复核不通过
- 被明显更高评分候选替换

### 7.2 B：ai-hedge-fund

运行频率：每周，重大财报或事件可触发临时复核。

代表性分析组：基本面、估值、技术、情绪、价值质量、成长，以及风险经理和组合经理。避免为了模仿人物数量而无限增加 Agent。

流程：

`独立信号 → 置信度聚合 → 目标权重 → 风险裁剪`

卖出由聚合信号转负、目标权重降零、基本面/估值反转、风险要求或组合再平衡触发。

### 7.3 C：TradingAgents

运行频率：每周，重大事件可触发临时复核。

保持原项目的核心组织结构：

`基本面/技术/新闻/情绪分析 → 多空辩论 → 研究经理 → 交易员 → 风险团队 → 组合经理`

只有组合经理批准且公共风控通过后才产生订单。卖出由新一轮看空结论、论点证伪、风险否决或组合经理退出决定触发。

### 7.4 D：ai-berkshire

运行频率：每月，财报发布后强制复核。

核心视角：

- 商业模式和护城河
- 财务质量和内在价值
- 行业格局和长期竞争
- 管理层、治理和尾部风险

买入要求商业质量、财务可信、治理无否决项且存在安全边际。卖出由论点证伪、护城河恶化、财务质量恶化、资本配置失控、达到合理价值或更优机会触发。普通价格波动不是主要卖出理由，但仍服从公共灾难风控。

### 7.5 F：串行融合

运行频率：每日轻筛、每周深度分析、每日持仓风险监控。

流程：

`200只研究宇宙`
→ `A式量化/技术初筛`
→ `C式多Agent研究与多空辩论`
→ `D式价值质量复核`
→ `B式组合构建和风险配置`
→ `公共风控`
→ `模拟成交`

F 采用逐层淘汰，不对 A/B/C/D 的最终动作简单平均。

卖出优先级：

1. 公共灾难风控
2. 投资逻辑或基本面证伪
3. 组合风险要求
4. 技术趋势破坏
5. 达到合理价值
6. 组合再平衡
7. 最长持仓期限复核失败

## 8. 模型控制

- 五套策略统一使用同一个 DeepSeek 官方模型
- 不使用第三方 API 代理
- 模型名在实施时通过官方当前能力确认后固定
- 统一基础温度、输出格式和调用超时
- 保存模型、参数、提示词哈希、原始响应和解析结果
- 模型升级必须产生新的实验版本，不覆盖旧实验
- 结构化解析失败时不猜测动作；记录失败并保持原持仓

F 可以调用更多阶段，但不能使用更强模型形成隐藏优势。

## 9. 历史验证

### 9.1 十年确定性回测

验证股票池、技术/财务规则、仓位、成交、费用、滑点、卖出和公共风控。按时间顺序推进，不随机打乱。

### 9.2 代表性 Agent 重放

选取覆盖以下状态的历史截面：

- 牛市
- 熊市
- 震荡市
- 流动性冲击
- 行业泡沫和崩塌
- 财报暴雷
- 中美市场制度差异

仅使用当时可获得的数据快照。每个截面保存完整输入、输出和成本。

### 9.3 前向模拟

历史引擎和数据质量门禁通过后，五套账户同日启动。前向模拟是完整 Agent 能力的最终可信评价；历史新闻不完整的回放结果只能作为辅助证据。

## 10. 错误处理与降级

- 数据缺失：标的进入不可交易状态，不用零值代替
- 行情陈旧：拒绝产生新订单
- 财务日期不可信：禁止用于历史策略判断
- 模型超时：有限重试；失败后保持持仓，不自动买卖
- 输出解析失败：记录原始响应并拒绝订单
- 重复调度：使用幂等运行键防止重复成交
- 部分市场休市：另一市场可独立运行
- 订单无法成交：保留明确状态和原因，不伪造成交
- 账本不平：立即停止该账户后续交易并报警

## 11. 测试策略

### 11.1 单元测试

- PIT 时间过滤
- A 股 T+1 和整数手
- 涨跌停、停牌和不可交易状态
- 美股交易日历
- 费用、滑点和汇率
- 风控裁剪
- 账本平衡
- 绩效指标
- 策略输出结构化解析

### 11.2 集成测试

- 数据快照到策略信号
- 信号到订单、成交、持仓和 NAV
- 公司行动处理
- 幂等重跑
- 数据源和模型失败降级

### 11.3 行为级验证

至少使用小型固定数据集验证：

- 收盘后信号不能按同日收盘成交
- 未来财报和未来新闻不可见
- A 股当日买入不能当日卖出
- 停牌或涨跌停时不会伪造成交
- 五套账户完全隔离
- 相同输入可复现相同确定性计算结果

## 12. 非目标

首版不做：

- 真实券商交易
- 高频或盘中策略
- 做空、杠杆、期权
- 手机 App
- 社交跟单
- 自动优化提示词以追逐回测收益
- 未经验证的策略自动晋级
- 用当前新闻伪造历史情绪回测

## 13. 交付顺序

1. 项目骨架和领域模型
2. PIT 数据层和固定测试数据
3. 模拟券商、账本、费用与风控
4. 股票池构建器和 200 只前向股票池
5. 确定性历史回测
6. A/B/C/D 策略适配器
7. F 串行策略
8. 代表性 Agent 历史重放
9. 前向模拟调度、报告和监控

每一步必须先有失败测试，再实现，再做行为级验证；不得用页面能打开代替交易行为正确。
